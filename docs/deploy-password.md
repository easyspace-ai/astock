# 公网部署：管理员账号初始化

面板部署在公网服务器时，**首个管理员账号的注册只允许本机或内网访问** —— 防止公网陌生人抢先注册、拿走超级管理员权限。

如果你在公网浏览器直接打开页面，会看到提示：

> 面板尚未初始化,请通过 SSH/本机浏览器访问以注册管理员

有两种方式解决，任选其一。

> 旧的 `AUTH_PASSWORD` 访问密码模式已下线：`.env` 中的该变量不再读取，`user_data/auth.json` 也不再参与登录。系统只认邮箱账号会话。升级前已有账号的部署直接用原邮箱账号登录；只有访问密码、尚无邮箱账号的部署，请按下文在本机/内网注册首个管理员。旧配置备份中的 `user_data/auth.json` 条目会被视为范围外文件并忽略。

---

## 方式一：环境变量预置管理员（适合 Docker / 自动化部署）

在 `.env` 文件（或 Docker / 系统环境变量）中同时设置：

```bash
ADMIN_EMAIL='admin@example.com'
ADMIN_PASSWORD='至少 6 位的密码'
```

启动时，**仅当系统还没有任何邮箱账号**，会用这两个值创建首个超级管理员；已有账号时不会覆盖。

### 注意事项

- 两个变量必须同时填写，缺一不会创建。
- 密码至少 6 位；明文只存在于 `.env` / 环境变量，落库的是 PBKDF2 哈希。
- `.env` 文件权限保持 `600`，**不要提交到 Git**。
- 账号创建后，后续的新增账号、改密码、权限组调整都在页面「管理后台 → 用户与权限」完成，环境变量不再生效。

---

## 方式二：SSH 端口转发

不用改配置，在你**自己电脑**的终端执行（不是服务器上）：

```bash
ssh -L 3018:127.0.0.1:3018 用户名@服务器IP
```

例如服务器是 `123.45.67.89`、用户名 `root`、面板端口 `3018`：

```bash
ssh -L 3018:127.0.0.1:3018 root@123.45.67.89
```

保持这个 SSH 连接**不要关**，然后在**自己电脑的浏览器**打开：

```
http://127.0.0.1:3018
```

此时后端看到的客户端 IP 是 `127.0.0.1`（本机），能通过校验，正常显示「创建账号」界面。注册成功的首个账号自动成为超级管理员。

**注册完成后**，SSH 连接可以断开 —— 账号已存入服务器，之后直接用公网地址 + 邮箱账号登录即可。

### 端口说明

上面的 `3018` 是默认端口。如果你用 `PORT` 环境变量改过端口（比如 `PORT=8080`），两处都要替换：

```bash
ssh -L 8080:127.0.0.1:8080 root@123.45.67.89
```

---

## 原理说明

- **为什么限制本机/内网？** 面板部署到公网后，任何人都能访问 URL。如果不限制，攻击者可以在你之前注册首个账号，把你的面板锁死。
- **本机/内网如何判断？** 后端检查客户端 IP 是否属于 `127.0.0.1 / ::1 / 10.x / 192.168.x / 172.16-31.x`。
- **SSH 转发为什么有效？** `-L` 把本机端口通过 SSH 隧道转发到服务器的 `127.0.0.1`，等同于在服务器本地访问，客户端 IP 变成 `127.0.0.1`，通过校验。
- **反向代理注意：** 若面板在 Nginx 等反代之后，需正确配置 `X-Forwarded-For` 头，后端据此取真实客户端 IP。

---

## 忘记密码怎么办

- 已启用邮件服务：在登录页点「忘记密码」，用已验证邮箱收验证码自助重置。
- 未配置 SMTP：用另一个管理员账号登录，在「管理后台 → 用户与权限」中重置对应用户密码；或使用 `ADMIN_EMAIL`/`ADMIN_PASSWORD` 重建一个全新数据目录（不会迁移旧账号，慎用）。
- `user_data/auth.json` 是旧模式遗留文件，删除与否都不影响邮箱账号登录。

---

## 两种方式怎么选

| | 环境变量 | SSH 转发 |
|---|---|---|
| 操作 | 改配置 + 重启 | 一条 ssh 命令 |
| 需要改配置 | 是 | 否 |
| 适合 | Docker / 自动化部署 / 不熟 SSH | 临时初始化 / 能 SSH 到服务器 |
| 后续改密码 | 管理后台或「个人中心」 | 同左 |
